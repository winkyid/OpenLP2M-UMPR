OpenLP2M - UMPR

Catatan implementasi untuk developer yang memelihara daftar kelompok KKN 51 UMPR 2026. Halaman ini menjelaskan sumber data, proses parsing, dan alur tampilan.

Arsitektur

Situs ini adalah aplikasi statis tanpa server atau proses build. index.html memuat list-url-spreedsheat.js sebagai konfigurasi 25 kelompok, lalu app.js mengambil data publik dan membangun antarmuka menggunakan DOM API. GitHub Pages dapat melayani berkas-berkas ini langsung dari root repositori.

index.html — halaman daftar dan dialog detail.

list-url-spreedsheat.js — URL spreadsheet per kelompok, termasuk parameter gid.

app.js — pengambilan data, parsing, pencarian, tabel native, dan tampilan spreadsheet mentah.

styles.css — gaya halaman, tabel, dialog, dan breakpoint mobile.

Sumber dan pemuatan data

  1. Konfigurasi URL

    Setiap objek kelompok menyimpan url_spreedsheet. Aplikasi membaca parameter gid dari URL itu untuk menemukan baris yang sesuai di HTML publik Google Sheets.

  2. Ringkasan kelompok — baris 3

    Elemen header baris memiliki ID {gid}R2. Sel ringkasan di baris tersebut berisi nama kelompok, jumlah mahasiswa, DPL, lokasi, dan keterangan. Aplikasi mengambil teks sel, memisahkan bagian berdasarkan tanda pisah, lalu mengisi metadata kartu dan dialog. Nama prodi di dalam tanda kurung siku pada bagian DPL tidak dipakai.

  3. Judul tabel dan anggota — mulai baris 4

    Baris judul tabel memiliki ID {gid}R3. Enam sel judul menjadi kolom tabel: No, NIM, Nama Mahasiswa, Program Studi (SIAKAD), Fakultas, dan Angkatan. Baris setelahnya diambil sebagai anggota; baris kosong dan baris tanpa nomor serta nama tidak ditampilkan. Dua baris dokumen sebelumnya dan baris ringkasan tidak masuk ke tabel native.

  4. Sinkronisasi dan kegagalan

    Saat halaman daftar dibuka, metadata 25 spreadsheet diminta secara paralel dengan Promise.allSettled. Hasil sukses dipakai untuk memperbarui kartu dan disimpan dalam cache memori agar tabel dapat dibuka tanpa fetch kedua. Kegagalan ditampilkan di status halaman dan dicatat ke konsol; membuka tabel untuk kelompok yang gagal dapat mencoba mengambil datanya kembali.

Contoh kode pengembangan

Cuplikan berikut menunjukkan kontrak inti sistem. Nama fungsi mengikuti implementasi di app.js; contoh bisa dijadikan dasar saat menambah fitur atau memperbaiki parser.

Dua mode tampilan spreadsheet

Buka di website

Menggunakan data baris 4 dan seterusnya untuk membangun tabel HTML native. Isi sel ditambahkan sebagai teks, bukan markup, dan area tabel memiliki scroll horizontal serta vertikal sendiri.

Buka spreadsheet

Memuat URL publik asli dalam iframe di dialog yang sama. Tidak membuka tab baru; tombol kembali menutup mode ini dan mengembalikan detail kelompok.

Prasyarat dan batasan

  • Spreadsheet harus dipublikasikan sebagai HTML dan mengizinkan request lintas origin dari GitHub Pages (CORS).
  • Urutan baris serta ID baris {gid}R2 dan {gid}R3 adalah kontrak parser; perubahan format sheet perlu diikuti perubahan parser.
  • Data dan daftar anggota bersifat publik mengikuti izin spreadsheet. Situs tidak menambahkan autentikasi atau menyimpan data ke server.
  • Thumbnail tetap memakai url_preview_thumbnail; URL kosong berarti antarmuka menampilkan placeholder.
  • Logo dimuat dari URL eksternal yang ditetapkan pada HTML, sehingga tampilannya bergantung pada ketersediaan host logo.
